# Project conventions

Read [AGENTS.md](../../../AGENTS.md), the applicable phase/package in [SOFTWARE_FACTORY.md](../../../docs/SOFTWARE_FACTORY.md), and relevant [ARCHITECTURE.md](../../../docs/ARCHITECTURE.md) sections; perform the first full architecture read required by AGENTS.md. These contracts own shared rules.

- Identify authorization, DEVELOPMENT/DEMO versus real-world mode, current phase and unmet dependencies before editing. A skill or plan is not implementation permission.
- Verify non-main branch and existing user changes. Define one bounded package: outcome, exact leased files, interface/schema ownership, acceptance cases and evidence. Adapt parallelism only under AGENTS.md; shared interfaces/config/lockfiles need one owner.
- Preserve the modular-monolith boundaries and owner-approved requirements. Extend existing conventions; do not scaffold speculative frameworks, duplicate instructions or versioned architecture files.
- Mark synthetic provenance, simulated approvals and limitations in outputs; do not promote fixture state or unavailable prerequisite into professional/full-phase approval.
- Route changed security, financial, evaluation and review/integration behavior to the corresponding project skill only when needed; do not load all skills by default.

Return the exact file scope, interfaces/dependencies, relevant contract references, acceptance evidence and remaining blocker. Report a demonstrable contradiction before changing the canonical architecture; do not silently reinterpret it.
